Not verified or implemented: live job availability, provider course access, hosted Auth configuration, a production database, model accuracy, evaluated model-assisted resume wording, external application success, hosted worker operation or containerized end-to-end grading, provider integrations or performance under load. The local identity stack is verified; hosted SMTP, hooks, secrets and schema deployment remain operator steps described in [Identity setup](IDENTITY_SETUP.md). Other design documents describe future acceptance gates. Course pages can apply bot protection, so the demo does not claim automated availability validation.

Module 10 contributes three provider-delay cases, seventeen upload/review cases and twelve feed/schedule cases to the passing 168-case integration suite. These cover actual queue/database authority, source registration, batch processing, immutable previews, provenance/publication, mobile/desktop administration, provider waits and crash redelivery, empty feeds, course CSV/uncertainty/closure and access denial. Successful feed replies/DNS are injected through the safe-reader network port; task/PGMQ/PostgreSQL/Next/browser execution is real. The actual Node adapter’s negative network path is tested; successful live-provider retrieval remains a deployment gate. Ordinary deployments retain an empty registry until real source permission/configuration is supplied. See [ingestion scope](INGESTION_SETUP.md).

Local operations recovery additionally passed same-snapshot backup/restore into an owned disposable database: 135 tables, 19 policies and 272 public routines, plus constraints/triggers/sequences, queue metadata/queued/archive content and an isolated send/archive probe. Intentional failure after target creation also verified database/archive cleanup. This is same-cluster local database evidence; Storage bytes, cluster loss, hosted configuration and full-environment disaster recovery are excluded.
