Screenshots in `docs/assets` come from the running app using `scripts/capture-demo.mjs`, not generated visual mockups. Mobile behavior was checked at 390 × 844; desktop captures used 1440 × 1100. Screenshots do not establish production accessibility conformance.

Not verified or implemented: live job availability, provider course access, hosted Auth configuration, a production database, model accuracy, evaluated model-assisted resume wording, external application success, hosted worker operation or containerized end-to-end grading, provider integrations or performance under load. The local identity stack is verified; hosted SMTP, hooks, secrets and schema deployment remain operator steps described in [Identity setup](IDENTITY_SETUP.md). Other design documents describe future acceptance gates. Course pages can apply bot protection, so the demo does not claim automated availability validation.

Module 10 contributes three provider-delay cases, seventeen upload/review cases and twelve feed/schedule cases to the integration suite (the initial module 10 checkpoint passed 168 cases). These cover actual queue/database authority, source registration, batch processing, immutable previews, provenance/publication, mobile/desktop administration, provider waits and crash redelivery, empty feeds, course CSV/uncertainty/closure and access denial. Successful feed replies/DNS are injected through the safe-reader network port; task/PGMQ/PostgreSQL/Next/browser execution is real. The actual Node adapter’s negative network path is tested; successful live-provider retrieval remains a deployment gate. Ordinary deployments retain an empty registry until real source permission/configuration is supplied. See [ingestion scope](INGESTION_SETUP.md).

Local operations recovery additionally passed same-snapshot backup/restore into an owned disposable database: 142 tables, 19 policies and 311 public routines, plus constraints/triggers/sequences, queue metadata/queued/archive content and an isolated send/archive probe. Intentional failure after target creation also verified database/archive cleanup. This is same-cluster local database evidence; Storage bytes, cluster loss, hosted configuration and full-environment disaster recovery are excluded. See [the exact procedure and outstanding gates](OPERATIONS_RECOVERY.md).

Administrator diagnostics add eleven real integration cases to the passing 206-case suite. Presence behavior and notice thresholds add four unit cases to the passing 120-case suite. The actual private browser screenshots and setup/retention limits are described in [operations setup](OPERATIONS_SETUP.md). These observations send no external alerts or provider calls; account erasure uses the separate domain service documented below.

Private account data portability contributes twelve real integration cases and three unit cases. The [account setup guide](ACCOUNT_DATA_SETUP.md) describes its 32 record groups, exact committed files, metadata/security exclusions, size bounds, expiry and owner/source cleanup. `scripts/check-account-worker-image.mjs` verifies an actual private ZIP round-trip and byte/manifest integrity inside the non-root production image without network or a writable filesystem. Trusted restore deletion replay, hosted transport at representative sizes and external telemetry remain unverified/pending.

Self-service live erasure adds fifteen actual integration cases and four unit cases. The [deletion guide](ACCOUNT_DELETION_SETUP.md) records its capability/lease policy, private progress, persistent recovery, late-object reclamation, audit/contact minimization and local ledger export. The full local suite passes 206 cases; backup-ledger overlay/off-host retention, hosted deletion and Storage-object restoration remain separate acceptance gates.
