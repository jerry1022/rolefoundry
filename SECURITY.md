# Security policy

The public static RoleFoundry demo is browser-local. Configured server deployments implement Supabase identity, invitation admission, verified roles, owner RLS, versioned consent and weekly quotas. Private preferences/evidence are implemented in module 02 with immutable history, optimistic revisions and reference-only invalidation events. Published catalog/source governance and private bookmark APIs are implemented in module 03, with anonymous projections that exclude drafts and private permission documents. Module 04 adds reviewed dictionary versions. Module 05 adds owner-scoped attempts, server-private answer keys, durable deterministic grading, atomic evidence publication and lease/deactivation/deletion guards. Administrator bank access is separately authorized. Fixed-choice scoring sends no data to providers and consumes no AI allowance. Module 06 adds versioned private matching inputs/results with freshness-checked owner RPCs and synchronous purge when a source evidence version is deleted. Module 07 adds anonymous rights-filtered course projections and owner-only plans/progress/practice references, with immutable resource versions, validated planning references and synchronous derived-content purge on evidence deletion. Independent owner practice references remain private and individually deletable. Module 08 adds private source storage, isolated document processes, owner-confirmed unreviewed claims, immutable grounded proposals/exports, session-bound expiring downloads and deletion-safe Storage cleanup. Document libraries receive no inherited service credentials; native-code containment limits and hosted controls are explicit in [resume setup](docs/RESUME_SETUP.md). Remaining career modules still use local demo data; no live AI provider or application submission service is connected. The public catalog inspector is not an authenticated admin panel. Do not enter sensitive information into the public demo.

Please report suspected vulnerabilities through GitHub's private vulnerability reporting for this repository when available. Otherwise open an issue asking for a private reporting channel without including secrets, personal information or exploit details. Never paste tokens or resumes into a public issue.

Keep local environment files untracked. Never expose a Supabase service key through a `NEXT_PUBLIC_*` variable. Follow [identity setup](docs/IDENTITY_SETUP.md), including the Auth hook and production SMTP/rate limits. The database guards deactivation and deletion during identity tasks; full account export/deletion orchestration and storage recovery remains a later module gate described in the [HLD](docs/HLD.md).

Only the latest scaffold release is maintained initially. A security fix does not imply that the planned production integrations have been implemented or audited.
